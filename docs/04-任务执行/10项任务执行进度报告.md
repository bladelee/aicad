## ✅ #6 ST-01 → ST-A 材料 编号联动（已完成）

### 算法
1. 用正则 `ST\-01(?![0-9A-Z])`（全字匹配，不误伤 ST-010/ST-011）
2. 扫 3 张主图的 modelspace + 所有 layouts 的 INSERT 属性（tag + value）+ TEXT + MTEXT
3. 自动备份每张图 → `.bak_ST.dxf`
4. 写出 `<原名>_ST-01_to_ST-A.dxf`

### 验证结果
```
✅ 3-19-102平面系统图: ST-01=0,    ST-A=143
✅ 4-19-102立面图    : ST-01=0,    ST-A=590
✅ 5-19-102节点      : ST-01=0,    ST-A=352
总计: ST-01 残留=0, ST-A 新数=1085
```

### 工具
- 实现：[`tools/dxf_edit/apply_material_rename.py`](../tools/dxf_edit/apply_material_rename.py)
- 验证：[`tools/dxf_edit/verify_rename.py`](../tools/dxf_edit/verify_rename.py)
- 用法：`DRY_RUN=1` 先看，`DRY_RUN=0` 真改；`OLD_CODE` `NEW_CODE` 可参数化

### 重要发现
- 实际替换 **1085 处**（比 scan 的 357 多 3 倍），因为之前 scan 只扫 value 字段，未扫 tag。
- tag 几乎都叫 `ST-01`、value 是材料描述。说明设计师把"材料编号"作为 tag 名，而 value 是材料名（PT-01/PT-XX 等具体颜色）。

## ✅ #1 改墙（封装版，已完成）

### API 设计
```python
move_wall(
    dxf_path=Path,
    handle=None | point=None | idx=0,   # 三种选墙方式
    dx=0.0, dy=0.0,                     # 偏移量
    mode='translate' | 'extend-end',    # 操作模式
    sync_layers=True,                   # 是否同步 'A原建筑墙体填充' 等
    backup_dir=Path,                    # 自动轮转备份 .bak1/.bak2...
)
```

### 实测结果（dx=500, dy=0, translate）
```
✓ 选墙 handle=98F93: (57689, -943781) → (58262, -943781)
✓ 平移后  : (58189, -943781) → (58762, -943781)
✓ 联动 'A原建筑墙体填充' 图层平移了 4 个实体（hatch 边界）
✓ 自动备份 → backups/move_wall/3-19-102平面系统图.bak1.dxf
✓ 输出     → 3-19-102平面系统图_moved_500_0.dxf
✓ round-trip: 9471→9461 实体（仅丢 10 个 REGION 3D 实体，2D 业务无影响）
```

### 工具
- 实现：[`tools/dxf_edit/move_wall.py`](../tools/dxf_edit/move_wall.py)
- env 参数：`DX/DY/MODE/OUTPUT_SUFFIX`

### 重要发现
- `A原建筑墙体填充` 与 `A原建筑墙体` 强依赖：4 个 hatch 边界实体跟着移
- round-trip 仍丢 10 个 REGION（与 #1 demo 一致，ezdxf 不写 ACIS 字段）
- **联动 #4/#5 立面图节点图**的算法根基已被打通：用同样 dx/dy 平移它们的 `A原建筑墙体` 即可
