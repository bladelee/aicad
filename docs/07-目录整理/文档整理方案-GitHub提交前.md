## 三、子目录规划原则（为什么这样分）

| 子目录 | 主题 | 入选标准 | 修改频率 |
|---|---|---|---|
| `01-产品` | 给客户/产品经理看的 | 权威对外文档、不写代码细节 | 低（版本稳定） |
| `02-方案` | 架构设计、技术选型 | 当前所有 ✅🆕 方案 | 中（按 phase 更新） |
| `03-计划与复盘` | 时间序列的过程记录 | 按"日期 + 阶段"命名 | 高（持续追加） |
| `04-任务执行` | 10 项联动改造执行链 | 任务排序/探查/进度/讨论 | 高 |
| `05-知识沉淀` | 领域知识 SOP 借鉴 | 不带时间戳、可复用知识 | 低（稳定后少改） |
| `06-工程实操` | 实战踩坑 / 实施日志 | "怎么把事情做出来"的过程 | 中 |
| `07-目录整理` | 整理元文档 | 关于文档本身 | 极低 |
| `99-归档` | 历史已取代的 | 顶部明标 ⚠️🗄️ | 不再修改 |

> 采用"两位数字前缀"既是排序锚点，也便于一眼区分"活文档"（01–07）和"死文档"（99）。
