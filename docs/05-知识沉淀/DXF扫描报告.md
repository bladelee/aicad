## 3. 跨图公共块定义（273 个！异常高）

### 3.1 ⚠️ 版权 / 作者块（必须避开）

| 块名 | 分布 |
|------|------|
| `2请勿改名` | 1 / 2 / 3 / 4 / 5（5 张全有）|
| `6联系作者` | 1 / 3 / 4 / 5 |
| `1尊重版权` / `4请勿商用` / `5商用授权` | 多张 |

**说明**：这是一份设计师从某个**商业 CAD 模板**购买的样本。这些块**不能动也不能删**——动了就是法律风险。

### 3.2 业务块（重点关注）

```
$TCHSYS$WIN2D      → 3/4/5 共有（TCH = 天正建筑软件的缩写！）
$TwtSys$xxx        → 天正 TWT 系统块（结构专业）
$WINLIB2D$xxx      → 窗库 2D 块
```

🔴 **关键发现**：这是**天正建筑（TArch / TWT）**软件画的图，不是纯 AutoCAD！

### 3.3 天正建筑带来的影响

- 天正在 AutoCAD 之上**包装了自己的对象模型**（墙、门窗是自定义对象，不是 LINE/POLYLINE）
- 转 DWG→DXF 后这些自定义对象会变成**代理实体**或扩展数据（XData）
- ezdxf 读到的可能是"代理实体外壳 + 大量 XData"，需要额外解析代码

## 4. ⭐ 材料编号 ST-XX（要求 #6 / #7 的核心）

正则匹配 `ST[-_/]?[A-Z0-9]+` 在 6 张图里只命中：

| 编号 | 出现位置 |
|------|---------|
| **ST-01** | 平面系统图（多处：`*U497.ST-01`、`王沧线条材质块.ST-01`）+ 节点（`*U67.ST-01`）|
| **ST-03** | 5-节点（`*U527.ST-01=ST-03`、`*U296.ST-01=ST-03`）|
| **ST-06** | 4-立面图（`*U468.ST-01=ST-06`）|

但**要求.txt #6 说**："材料表中 ST-01，改成 ST-A 后，平面，立面，节点，顺改"。

### 4.1 矛盾与排查

**用户要求改的应该是 2-材料表.dxf 里的 ST 列**，但本次扫描：
- 2-材料表 = 0 实体（全在 layout 里未扫到）
- 命中的 ST-01 在 **attribs**（块属性 TAG=ST-01）

**结论**：必须**升级 scan_dxf.py 让它扫 layouts**，才能看到完整的 ST-XX 材料表和Layout1 的封面/目录内容。

### 4.2 已知要求与映射

```
要求 #6 要求：           实际扫描发现：
ST-01 → ST-A            ST-01 在 3 张图出现（块属性）
                       ST-03 只在节点
                       ST-06 只在立面
                       （没有 ST-A，说明要替换字符串）
```
