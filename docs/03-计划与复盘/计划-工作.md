## ⚠️ 关键预先决策（开工前需要你拍板）

下面 3 个抉择决定 Phase 0-A 的技术路线，见 [`任务-讨论.md`](../04-任务执行/任务-讨论.md) 详细分析（如果你看到这份文档不存在，说明我还没写）：

### 决策 1：DWG→DXF 转换工具
- **选项 X**：装 ODA File Converter（合规、保真度最高，你 EULA 责任）
- **选项 Y**：用 LibreDWG（镜像外提供，保真度略低但够用）
- **选项 Z**：直接用 ezdxf 写原生 DWG（最高风险，需要装 ezdxf 的[dwg read support](https://ezdxf.mozman.at/docs/dxfentities/)，仍不稳定）

**推荐 X**：你执行 `floorplan-mcp/install_oda.sh` 装到本机，挂载进容器。

### 决策 2：图纸关联用什么作锚点
- 选项 1：图层名（最简单可靠，但设计师未必遵守严格图层规范）
- 选项 2：块名 + 属性（如 `WALL_LAYER_01`、`ST-01` 块属性）
- 选项 3：空间坐标近似匹配（最复杂但鲁棒）

**推荐 1+2 组合**：先用图层名/块名/属性文本扫，建立第一版"关联图谱"。

### 决策 3：DWG 的"联动"是"真关联"还是"重画"
- 选项 1：写 AutoCAD 的 `XREF`/`DATAEXTRACTION` 等真关联机制（最难，依赖 AutoCAD 特性）
- 选项 2：用脚本"假联动"（改完后程序主动去其他图纸找到对应元素改）

**推荐 2**：MVP 阶段先用"假联动"。真关联机制 Phase 2 再考虑。
