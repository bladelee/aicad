## 三、已解决的关键 bug / 错判 / 缺口（按严重度）

### P0 — "门是 INSERT" 假设错（推延 #10 一个量级）

- **错判**：网上说"门/窗是 INSERT 块"，先入为主以为改 xscale 就行
- **实测**：`probe_doors.py` 跑了 7 分钟，发现门窗图层里 INSERT 只占少数；大部分是 `LINE`(401)/`ARC`(307)/`LWPOLYLINE`(228) 拼起来
- **教训**：**永远先 count + grep 实测，再决定算法**。**字符串/类型分布是免费的探针**。

### P0 — "目录在 1-封面" 假设错（误导 #8）

- **错判**：以为封面 Layout1 含目录条目（"1→封面"、"2→材料表" 之类）
- **实测**：427 个 TEXT 全是施工/材料规范说明，**完全没目录条目**
- **教训**：**用户原话里的"目录"可能指图纸命名前缀（1-/2-/3-）**，不是图纸内的目录对象。**用户澄清后 #8 反而变成简单的"按顺序联动处理"**。

### P0 — "地坪/天花是单独 DWG" 假设错（误导 #2）

- **错判**：原报告假设存在 `地坪.dwg`、`天花.dwg`（也算"工程行规"）
- **实测**：用户明确"就在 3-平面文件里"，立即扫描发现 14 个 `F地坪*/S天花*/C天花*/L天灯` 图层共 1754 个实体
- **教训**：**对图纸结构有疑问，先问用户或先扫一遍实体的图层数据**，不要凭网上"工程行规"猜。

### P1 — 跨图坐标匹配被认为是难题

- **原认知**：3 张图坐标系不同（X 跨度差几千），需要"近似匹配算法"
- **实测发现**：根本没有这回事！Designer 在图纸里**显式建了 `Z节点索引`/`Z立面索引` 块，attrib 就是目标编号**（`DE-02`/`1EA-08`/`FU-03` 等）
- **教训**：**优先找显式元数据（attrib、XData、APPID），再做坐标算法**。

### P2 — ST 编号 scan 漏了 tag（数量低估 3 倍）

- 第一次 scan 看到 ST-01 357 处，真改时 1085 处
- 原因：scan 只扫 INSERT 的 **value**，没扫 **tag**；但本图 tag 名字本身就是 ST-01
- **教训**：扫描脚本必须 typetag + value 双扫。

## 五、本阶段沉淀的最佳实践 / 反模式

### ✅ 最佳实践（继续保持）

1. **DRY_RUN 模式先跑验证**：apply_material_rename 先 DRY_RUN=1 看替换次数符合 scan 数，再 DRY_RUN=0 真改。
2. **正则用 word boundary**：`ST\-01(?![0-9A-Z])` 全字匹配，避免误伤 ST-010/ST-011。
3. **3 种选墙方式**：handle / point / idx 三种参数化，覆盖不同使用场景（用户给具体墙 / 给坐标 / 给序号）。
4. **自动备份轮转**：每次改文件先 `.bak1.dxf`，第二次 `.bak2.dxf`，避免覆盖早期备份。
5. **round-trip 验证**：改前实体数 / 类型分布 / 关键 handle → 改后对比，量化保真度。
6. **探查脚本可重入**：每个 probe_*.py 都能独立运行，不依赖外部脚本，便于调试。
7. **目录重构"软链兼容"**：旧引用 `dwg/` → `samples/19-102/` 软链，保留兼容。

### ❌ 反模式（避免重复）

1. **不要先复杂后简单**：8 月 8 日就建了一堆旧的 [DWG](DWG) 探针但散乱在 dwg/ 下，9 日 03:34 整理目录前才回过头来"在哪找脚本"成问题。→ **目录结构应和数据规模一起设计**。
2. **不要过度假设工具行为**：ODA 27.x 已无 CLI、ezdxf 1.4.4 materials bug、门不是 INSERT —— 3 处假设都错了。→ **每引入新工具必先做 1 行实测**（`strings` / `type count` / `--help`）。
3. **不要等用户问再确认范围**：#2/#8/#10 在已复工时才回头探查，错了再回头修。→ **开工前先用 5 行 Python 扫一遍数据分布**，把疑问写进"待用户确认"。
4. **probe_tasks.py 跑太慢没察觉**：扫描器遍历 6 张图所有 layout 所有 attribs，未做 timeout/进度条。→ **耗时长操作必须加进度提示 + 超时 kill**。
5. **shell heredoc 嵌套引号炸裂**：写 `docker run -lc '...python<<EOF...EOF'` 经常乱。→ **改用独立 [.py](.py) 文件挂载跑**，放弃 heredoc。
