# floorplan-mcp 发布与部署完整方案

> **创建**：2026-08-09
> **状态**：⚠️ **设计阶段，待用户确认**
> **背景**：用户原话 "如何发布与部署，请给出完整方案，我们要准备上线发布了。" + 之前确认 "客户是主要在用 Windows + AutoCAD，但我们要提供的是一个 ai cad，autocad 留给他做手工调整用的。docker 可以安装在云端，mvp 阶段可以安装在本地。"
> **关联**：本方案补全 `README-客户部署使用手册.md`（设计师视角）和 `floorplan-mcp/Dockerfile`（构建视角）之间的**发布工程空白**——把"开发机镜像"如何变成"客户可用产品"讲清楚。

## 0. TL;DR（决策摘要）— **已确认 ✅ / 2026-08-09**

| 维度 | 选择 | 备选（不选的原因） |
|-----|------|-------|
| **交付物** | `floorplan-mcp-x86_64.tar` (≈3.5GB) + 安装器 + Goose + 文档 | 仓库代码（客户需打构造，不行）|
| **镜像分发** | ✅ **ghcr.io 公开 repo** | Aliyun 私有（v1.0 商业化再说）/ 纯 tar 包（升级难）|
| **部署形态** | ✅ **客户端本机 Goose + 容器在服务器（形态 A + B 混合）** | 纯本机（升级难统一）/ 纯云（高化复杂度）|
| **C4 优先** | ✅ **先做 CLI 形态**（C4-α→β→δ，约 1.5 天）| 先做 MCP（设计师受益但要三层完整 in one shot）|
| **客户平台** | Win10/11 x86_64 设计师端，Linux 服务器端上装 docker | Arm 架构不支持（libredwg 编译问题）|
| **主镜像内容** | ✅ **不含 libredwg**（决策 4）：libredwg 独立镜像，客户自 pull | 含进主镜像（GPL 传染风险）|
| **前端** | **Goose Desktop 桌面** 为主（已支持 stdio MCP）| OpenWork 远程模式 Phase 1.5 再推 |
| **AutoCAD 关系** | 客户保留 AutoCAD 做"手工精修"，**本产品不试图取代**，是补充 | — |
| **网络要求** | 本体镜像可 ghcr 公开拉；**LLM API 需订阅客户自带**（OpenAI/Anthropic）| 内置 LLM：成本/许可不可行 |

**最大风险**：客户公司装 Docker Desktop 门槛。
**最大卖点**：AI 改图 + 多图联动（Goose 一句话 → 同改 3-平面 / 立面 / 节点）。

## 1. 产品形态（明确"我们交付什么")

### 1.1 物理交付物（一个产品包 `floorplan-suite-x.y.z-windows-x86_64.zip`）

```
floorplan-suite-0.1.0-windows-x86_64.zip
├── installer/
│   ├── floorplan-setup.exe          ← 一键安装器（Inno Setup 打包）
│   └── install.bat                  ← 备选批处理（无 GUI 装）
│
├── images/
│   ├── floorplan-mcp.tar            ← 主镜像 (~3.5GB)
│   └── libredwg-cli.tar             ← DWG↔DXF 转换镜像 (~1GB)
│
├── docker/
│   ├── Docker.Dockerfile            ← Docker Desktop 静默安装参数
│   └── check-docker.ps1             ← PowerShell 自检
│
├── client/
│   ├── Goose-Setup.exe              ← Goose 桌面客户端（嵌入式下载）
│   └── mcp-config.json              ← Goose 识别 floorplan-mcp 的 MCP 配置
│
├── docs/
│   ├── 快速上手.pdf                 ← 5 分钟上手（含图）
│   ├── 部署手册.pdf                 ← IT 管理员 10 分钟部署
│   └── 故障排查.pdf
│
├── samples/
│   ├── test-apartment.dwg           ← 演示图（小户型）
│   └── test-apartment.dxf
│
└── README.txt                       ← "请双击 installer/floorplan-setup.exe"
```

### 1.2 三个产品形态（同一交付物，三种部署）

| 形态 | 谁用 | 安装位置 | 难度 |
|------|------|---------|------|
| **A. 本机一体化** | 个人设计师 / MVP 客户 | 客户 Win 本机 | ★★ 装 Docker + Goose |
| **B. 公司内网服务器** | 设计公司多人共用 | 内网 Linux 服务器 | ★★★ IT 部署一次，员工零装 |
| **C. 公有云 SaaS** | 多公司订阅 | 阿里云/腾讯云 | ★★★★ HTTPS + 鉴权 + 监控（Phase 2）|

→ **MVP 专做形态 A**，形态 B/C 留 roadmap（见 §9）。

### 2.1 版本号策略（SemVer）


- **patch** (0.x.Y)：bug fix，镜像兼容
- **minor** (0.Y.0)：新工具，向后兼容
- **major** (Y.0.0)：架构变化，可能需要客户重装镜像

### 2.2 GitHub Actions 流水线

```yaml
# .github/workflows/release.yml
name: release
on:
  push:
    tags: ['v*']
  workflow_dispatch:

jobs:
  build-and-release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      # 1. build 主镜像
      - name: Build floorplan-mcp
        run: |
          docker build -f floorplan-mcp/Dockerfile \
            -t ghcr.io/<org>/floorplan-mcp:${{ github.ref_name }} \
            -t ghcr.io/<org>/floorplan-mcp:latest floorplan-mcp/

      # 2. build libredwg 镜像
      - name: Build libredwg-cli
        run: |
          docker build -f tools/dwg_to_dxf/Dockerfile.libredwg \
            -t ghcr.io/<org>/libredwg-cli:${{ github.ref_name }} \
            -t ghcr.io/<org>/libredwg-cli:latest tools/dwg_to_dxf/

      # 3. push 镜像
      - run: |
          echo ${{ secrets.GITHUB_TOKEN }} | docker login ghcr.io -u ${{ github.actor }} --password-stdin
          docker push --all-tags ghcr.io/<org>/floorplan-mcp
          docker push --all-tags ghcr.io/<org>/libredwg-cli

      # 4. 跑 smoke test（pytest 在镜像里包好）
      - run: |
          docker run --rm ghcr.io/<org>/floorplan-mcp:${{ github.ref_name }} \
            /opt/FreeCAD/usr/bin/python -m pytest /opt/floorplan/tests/

      # 5. 打 tar 包
      - name: Save images as tar
        run: |
          mkdir -p dist/images
          docker save ghcr.io/<org>/floorplan-mcp:${{ github.ref_name }} \
            -o dist/images/floorplan-mcp.tar
          docker save ghcr.io/<org>/libredwg-cli:${{ github.ref_name }} \
            -o dist/images/libredwg-cli.tar

      # 6. 打产品包 zip + release
      - name: Build product zip
        run: scripts/build-suite-zip.sh ${{ github.ref_name }}

      - uses: softprops/action-gh-release@v1
        with:
          files: dist/floorplan-suite-*.zip
```

## 3. 形态 A：客户本机一体化部署（MVP 主推）

### 3.1 客户硬件/OS 最低要求

| 项 | 最低 | 推荐 |
|---|------|-----|
| OS | Win10 22H2 / Win11 | Win11 |
| CPU | 4 核 x86_64（**不支持 ARM**，因 libredwg 编译）| 8 核 |
| 内存 | 8 GB | 16+ GB |
| 硬盘 | 30 GB 可用（镜像 5 + 数据 25）| SSD 50 GB |
| 软件 | Docker Desktop 4.35+ | Docker Desktop 最新稳定版 |
| 网络 | 装 LLM API key 必须能连 OpenAI/Anthropic | — |

### 3.2 客户安装步骤（10 分钟，6 步走）

```
Step 1. 解压产品包 floorplan-suite-0.1.0-windows-x86_64.zip
Step 2. 双击 installer/floorplan-setup.exe（Inno Setup 引导）
        → 自动检查 Docker Desktop 是否就位（没装弹引导）
        → 自动 docker load 两个 tar 镜像（5 分钟）
        → 自动写到 ~/dwgs/ 工作目录
        → 自动启动 floorplan-mcp 容器（restart=unless-stopped）
        → 自动打开 Goose 桌面 / 或装 Goose
        → 自动写入 Goose 的 mcp-config.json
Step 3. 把 DWG 文件放到 C:\Users\<用户名>\dwgs\
Step 4. 双击桌面 "Floorplan Goose" 图标
Step 5. 自然语言对话测试："列一下 dwgs 目录里的图"
Step 6. （首次用真实项目时）Goose 提示输入 LLM API key
```

### 3.3 卸载（控制面板 → 卸载程序）

```
- 删 docker images: docker rmi floorplan-mcp libredwg-cli
- 删 ~/dwgs/ 下的备份（.bak.*）  ← 可选择保留
- 删 Goose 配置 ~/.config/goose/mcp-config.json 里的 floorplan 段
```

## 4. 形态 B：公司内网服务器部署（多人共享）

### 4.1 部署拓扑

```
公司内网（10.x.x.x）
┌────────────────────────────────────────────────┐
│  Linux Server（IT 一次性装好）                  │
│  Docker daemon + floorplan-mcp:latest          │
│  暴露 https://floorplan.internal:3000          │
│                                                │
│  - 4 CPU / 16 GB RAM / 200 GB SAN              │
│  - 各员工 ~/dwgs 通过 SMB 挂载到 /shared       │
└────────────────────────────────────────────────┘
              ↑
              │ HTTPS + 公司 SSO (后续)
              │
   ┌──────────┴────────────┐
   ↓           ↓           ↓
设计师 PC    设计师 PC    设计师 PC
(Goose)     (Goose)      (Goose)
```

### 4.2 IT 部署清单

```bash
# 1. Linux 服务器（CentOS/Ubuntu）装 Docker
curl -fsSL https://get.docker.com | sh

# 2. 把产品包 ftp 上去 + 加载镜像
tar xf floorplan-suite-0.1.0-linux-x86_64.tar.gz
docker load -i images/floorplan-mcp.tar
docker load -i images/libredwg-cli.tar

# 3. 配置 streamable_http server（Phase 1.5）
cat > /etc/floorplan/docker-compose.yml <<EOF
services:
  floorplan-mcp:
    image: floorplan-mcp:latest
    restart: unless-stopped
    ports: ["3000:3000"]
    volumes:
      - /shared/dwgs:/data
    environment:
      FLOORPLAN_TRANSPORT: streamable_http
      FLOORPLAN_HTTP_AUTH_TOKEN: "\${AUTH_TOKEN}"   # 公司共享 token
EOF

# 4. 启动
docker compose up -d

# 5. 员工 Goose 配置
cat > goose-mcp-config.json <<EOF
{
  "mcpServers": {
    "floorplan": {
      "url": "https://floorplan.internal:3000/sse",
      "authToken": "员工 token"
    }
  }
}
EOF
# 分发给员工
```

### 4.3 难点（IT 必须解决）

- **HTTPS 证书**：内网证书或 Let's Encrypt；不走 HTTPS Goose 不接
- **共享文件权限**：`/shared/dwgs` 用 SMB 多人写要小心，建议每人子目录
- **审计日志**：所有写操作走 `_safety.make_backup()` 已留 .bak，但要加 mcp_server 层 access log
- **会话隔离**：MVP 不做（所有人的 goose 都看 /data 全部），Phase 2 加 `FLOORPLAN_USER_DIR`

## 5. 形态 C：公有云 SaaS（Phase 2 远期）

### 5.1 架构 sketch

```
Internet
   ↓ HTTPS
[ALB / API Gateway]
   ↓
[floorplan-mcp autoscale group on ACK/ACK]   ← 主服务
   ↓
[RDS for user/project metadata]
[OSS/S3 for DWG storage]
[Redis for session]
[LLM API: 通义千问 / GPT-4o]
```

### 5.2 额外要做的（不在 MVP）

- 多租户：每个公司一个 namespace，OBS bucket 隔离
- 鉴权：OAuth2 + 公司 SSO
- 计费：按 DWG 处理次数 + 存储 GB
- SLA：99.5% 月运行率
- 合规：DWG 加密存储 / 跨境数据流动报备（用国内云）

→ **不在 MVP 范围**。本方案只保证形态 A 可上线，形态 B 是 stretch。

## 6. 数据安全 / 备份

### 6.1 客户家目录布局（形态 A）

```
C:\Users\<user>\
├── dwgs\                       ← 客户工作区
│   ├── 客厅.dwg
│   ├── 客厅.dxf                ← libredwg 转换后
│   ├── 客厅.dxf.bak.001        ← 每次改前自动备份
│   ├── 客厅.dxf.bak.002
│   └── demo_outputs\           ← 每个 task 一次输出
│       └── 客厅_moved_E6037.dxf
└── floorplan\
    └── logs\                   ← MCP server 日志
```

### 6.2 备份策略（已有，写明保证）

- **永远不动原 DWG**：所有修改都走 DXF 产物 → AutoCAD 改完客户自己回写
- **写前自动备份**：核心函数调 `_safety.make_backup(path, max_keep=10)`，保留最近 10 份
- **回滚 = 一行命令**：`floorplan restore --dxf ... --bak bak.N.dxf`，30 秒回滚
- **每周末 IT 备份 `/shared/dwgs`**（仅形态 B）

### 6.3 隐私声明

- 客户 DWG 文件**永不上传到我们服务器**（形态 A）
- LLM API 调用：MCP 协议中是把 tool 调用元数据发到 LLM；**图纸几何数据**是否发取决于工具实现
  - 我们的工具默认**不**把 DXF 内容上传给 LLM，只发摘要（如"墙 1A2F 长度 10000mm"）
  - 客户若有"全图给 AI"的需求，加显式开关 `share_full_geometry=true`

## 7. 授权与许可

### 7.1 我们自己的代码 / 镜像

- **MIT License**（让客户/合作伙伴零障碍集成）
- 商业产品名 "floorplan-mcp" 也是 MIT

### 7.2 用到的开源组件（必须列在 LICENSES.txt）

| 组件 | License | 注意事项 |
|------|---------|---------|
| FreeCAD 1.0.2 | LGPL-2.1 | 打包进镜像 OK，但改 FreeCAD 源码需开源 |
| libredwg 0.14 | GPL-3.0 | **传染性**！我们镜像若分发 libredwg 二进制 → 整个镜像 deriv 需 GPL 化 |
| ezdxf 1.4 | MIT | 无问题 |
| matplotlib | PSF-based | 无问题 |
| ODA File Converter | 专有 EULA | **不打包**，让客户自装挂载 |
| Goose Desktop | Apache-2.0 | 客户端，可重分发 |

**GPL 风险决策点（待用户选）**：
- 🅐 **接受 GPL 传染**：镜像整体打包后以 GPL-3.0 发布
- 🅑 **规避 GPL**：libredwg 单独镜像（已实现），客户自行 docker pull；主镜像 floorplan-mcp 内**不含** libredwg 二进制
- 🅒 **静态链接 libredwg 进 ezdxf**（技术性规避）：未证实可行，留作研究

**推荐 🅑**（已是现状）。

### 7.3 字体 / 商标

- 镜像里用 DejaVu / Noto 字体（开源）
- AutoCAD 是 Autodesk 商标，文档中不要说"取代 AutoCAD"，要说"补充 / AI 辅助"
